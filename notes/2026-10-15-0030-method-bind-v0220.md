# The method checkout bound read-only (engine 0.2.20, backlog L7, roadmap W4)

## Goal

The executor bound a step's module directory, its inputs' parents and the step directory, so a
method's shared code beside the modules was invisible inside the container; the Xenium method
copied a six-file R library into every R module (`scripts/sync-rlib.sh`) and a plotting helper
into two Python modules (code review P1.4).

## Done

- `Job.ro_bind_paths`; `steps.job_for`, the judgment's pre- and post-script jobs and the control
  generator fill it with the method root; `apptainer.bind_set` emits `<host>:<container>:ro`,
  keeps the symlinked alias, drops a read-write bind nested under it (the module directory) and
  drops it under a kept read-write ancestor. The local executor needs nothing. No provenance
  field: the checkout's SHA and dirty check at run open pin the shared code.
- Tests: `test_m11.py::test_apptainer_binds_the_method_checkout_read_only` (the three cases);
  `test_steps.py::test_engine_step_sees_shared_code_beside_the_modules` (a toy module importing
  `modules/_shared/` runs under the local executor; the job carries the bind).
- Design 10.3; DECISIONS; L7 to `backlog-done.md`; version 0.2.20, golden, lock; full suite,
  ruff, mypy, no-biology green.
- Method `v0.6.0-rc15`: the R modules source `modules/_rlib` relative to themselves
  (`stringency_io.R`'s `rlib_dir` likewise), the two QC modules import `modules/_pylib/qc_plots.py`;
  the `rlib/` copies, the second `qc_plots.py` and `sync-rlib.sh` removed; the ten modules that
  changed and the three pipelines pinning them bumped a patch version; `requires` engine
  `>=0.2.20`; CI and the test scripts no longer check copies. Lint clean; `tests/run_r.sh` and
  `controls/synthetic_run.sh HEAD` under the dev engine (the Python QC chain through the engine
  with the read-only bind; the R modules under apptainer with `--bind $ROOT`).

## Learned

- A read-only bind that contains the module directory makes the module's own files read-only in
  the container, which nothing writes; outputs go to the step directory. Had a module written
  beside itself this would have surfaced here.

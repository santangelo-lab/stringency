# 2026-11-04 15:00: the bootstrap on a Mac under the beta's setup (0.2.39)

**Goal.** The owner reran `stringency-beta setup` on the MacBook against the v0.2.38 channel and
the bootstrap ended "the engine's bootstrap failed" after a complete install. Two findings in
its output.

**Done.**
- `bootstrap.sh`'s closing text read the executor with `sed` over the user's config file and
  (since the morning's `<prefix>/config.yml`) the install's; a missing file makes `sed` exit 2,
  which under `set -euo pipefail` ends the script after everything is installed. The install's
  file never exists at bootstrap time (the beta writes it after), so every v0.2.38 bootstrap
  failed at its last step; v0.2.38 without the second file failed on any machine with no user
  config. Now the two files go through `cat ... || true` into `sed`.
- `install.sh` chose `/Users/jimrose/Projects/stringency_proj/stringency-beta/cli/.venv/bin/python3`
  (Python 3.14, the beta CLI's own venv, first on PATH under `uv run`): macOS has no system
  3.12, and the third candidate was `command -v python3`. An engine linked to another venv's
  python breaks when that venv is rebuilt. `pick_python` now refuses an interpreter whose
  `sys.prefix` is not its `sys.base_prefix`, so the Mac falls through to uv's managed 3.12 as
  the S1 spike had.
- `tests/test_scripts.py` runs both pieces of shell as extracted from the scripts.
- Version 0.2.39. The `warning: refs/tags/v0.2.38 ... is not a commit!` in the same output is
  git's note on a shallow clone of an annotated tag (every engine tag is one); harmless.

- CI policy (the owner, 2026-11-04): the macOS job runs on every push to main and on a pull
  request only when it carries the `macos` label; hosted macOS arm64 runners left this PR's job
  queued and unassigned ("not acquired by Runner of type hosted even after multiple attempts",
  "capacity constraints") twice in two days. `pull_request` events include `labeled` so adding
  the label starts the run.

**Learned.** A `set -e` script's last decorative line can fail the whole run; anything read for
display goes through `|| true`.

**Altered.** Nothing in a contract.

**Open.** The beta channel pins v0.2.39 (`setup` also scrubs the CLI venv from the bootstrap's
environment and writes the site config first, so the closing text reads `local`). The owner
reruns `setup` on the Mac; `UV_VENV_CLEAR=1` rebuilds the engine venv on the right python.

**Verify.** `uv run pytest tests/test_scripts.py`; on the Mac, `setup` ends with the doctor report.

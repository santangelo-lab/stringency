## Learned

- `bind_set` let a path named in the job's stdin document override an explicit read-only bind,
  so an `exec` step's inputs would have been writable under apptainer; fixed in S3, with the
  method root named on the plan instead of derived from the module's path (an exec module lives
  in its step directory, and the old rule would have bound `runs/` read-only).
- A tool's positive control cannot run through the pipeline's ancestors: from `toy-engine` the
  filter dropped rows below 10 and the truth table could not hold from both routes. A module
  listing `open` is controlled alone, under a mode it admits (an open-only tool from a pipeline
  project was blocked by `topo.undeclared_step` until then).
- `coerce_value` reads `--set correction=none` as null, so the toy's `none` option cannot be
  set from the CLI; `param.schema_invalid` now blocks it (backlog L39).
- A cited figure from an uncontrolled tool makes the answer untested, as the rule says; the
  chain test controls both tools first.
- `uv sync --all-groups` (run to pick up the toy plugin's version) removed the hand-installed
  `stringency-singlecell` from this checkout's environment; `test_compat.py` had been failing
  on the clean tree because of that extra plugin in the coverage header, and passes now.
- An open run's `next` is exit 0: it waits for the next question, not for the engine.

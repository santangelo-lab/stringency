# 2026-11-05 18:00: what the beta's desktop app asked of the engine (0.2.40)

**Goal.** Stringency Desktop (the beta repository's `app/`, work packages A2 to A6, built on the
owner's MacBook 2026-11-04 and 2026-11-05) left three things for the engine in its notes. This
session closes them with the CLI side in the beta repository (branch `cli-for-app` there).

**Done.**
- `git.clone_at` from a shallow source. The beta's `setup` keeps each method as `git clone
  --depth 1 --branch <tag>` under `<prefix>/methods/<name>`, and `init --method
  ~/.local/lib/stringency/methods/toy@v0.3.1` (the local-path form) failed on the Mac
  2026-11-04 while the GitHub URL at the same tag worked. Reproduced on PROTSEQ: a shallow
  repository advertises its tag but a full `fetch --tags` from it is rejected ("shallow roots
  are not allowed to be updated"; `fetch.updateShallow` does not help), so the checkout found
  no `v0.3.1`. When the checkout fails, `clone_at` now fetches `--depth 1 --tags` and tries
  again; the project's `method.git` is then shallow, which every later git fact
  (`head_sha`, `is_dirty`, `blob_hash`, `tag_sha`) reads all the same. `tests/test_git.py`.
- `review --serve --projects <dir>` with nothing under the directory yet serves an empty board
  ("No project is running.") and the first project appears on the next scan, instead of
  refusing with "needs --project or --projects". A beta tester's console starts at login
  before any project exists; the app showed a refusal screen for that. `discover` still refuses
  when neither a project nor a directory is given. `tests/test_review_serve.py`.
- `flag --via app`: the desktop app relays the person's words outside any harness session and
  scrubs the session variables from the engine's environment, so its flags were recorded as
  `tty`; `app` is the honest value, beside `web`, `relayed` and `tty`, which stay detected and
  cannot be given (`flags.VIA_GIVEN`). `tests/test_flags.py`; a DECISIONS entry.
- Version 0.2.40; known-good row; the golden methods paragraph.

**Learned.** `git clone --depth 1` makes a repository that cannot be cloned from in full; a
shallow fetch from it is the only form git accepts. `fetch.updateShallow` is about the
fetching side's own shallow file, not the source's.

**Altered.** `via` on `flags` takes a fourth value, `app` (DECISIONS 2026-11-05); `discover`
returns an empty list for directories with no project rather than raising.

skill's `install-latest.sh`, which the owner runs).

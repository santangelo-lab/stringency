# Script drift: the code that ran is the code present at run open

## Goal

Answer whether stringency ensures the code the agent uses for analysis is saved, and close the
gap found: `repro.dirty_tree` checks the method tree at run open only, so a module script edited
afterwards ran under the run's SHA with nothing in the trace, and for operator steps the engine
never hashed what ran.

## Done

- One commit on `main` (after 0d419f6): run open captures the blake3 of every module entry
  script (`run_events` `captures`.`script_blobs`); the engine hashes the script again before it
  runs one and at `submit`; `executions.script_blob` (migration `0003`) records it; the ticket's
  job spec carries `script_blob` at ticket time; `exec.script_drift@1` (post, scope `*`, block)
  fires when the hash at execution differs from the hash at open. Comparing with the tree at
  open keeps `--allow-dirty` runs consistent. Judgment modules have no script and are exempt.
- Must-fire and must-pass in `tests/test_gate.py`; operator edit, engine edit, clean run, and
  allow-dirty run in `tests/test_steps.py`. Design 6.5, 9.1, 9.4 and `spec/trace-schema.md`
  updated; two DECISIONS lines; `spec/improvements.md` gains section G.
- The methods paragraph spells counts to ninety-nine (the toy now evaluates twenty-one
  predicates and the count opens a sentence).

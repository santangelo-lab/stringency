# 2026-11-04 10:00: the template's lockfile environments (beta M3)

**Goal.** Work package M3 of the beta-tester implementation plan: the method-repo template
carries one lockfile environment of each kind, so a method author on a laptop starts from the
convention the scanpy method proved (its `envs/scanpy-agent/`) instead of from an image.

**Done.**
- `templates/method-repo/envs/example-py/`: `pyproject.toml` (pandas, matplotlib, pyyaml;
  Python 3.12; `tool.uv.environments` and `required-environments` for Linux x86_64 and macOS
  arm64, as the scanpy method's) and its `uv.lock` (15 packages). `uv sync` in a copy on PROTSEQ
  builds it and imports the three.
- `templates/method-repo/envs/example-r/`: renv's scaffold (`.Rprofile`, `renv/activate.R` for
  renv 1.2.4, `renv/.gitignore`), a `DESCRIPTION` naming `jsonlite` and `ggplot2` (what
  `modules/_rlib/stringency_io.R` loads), `renv/settings.json` with the explicit snapshot
  type, and `renv.lock` (the two, their dependencies and renv: 19 packages) against the Posit
  snapshot `https://p3m.dev/cran/2026-09-01`, made in the `xenium-r` 0.2.0 image with
  `renv::lockfile_create`. In a copy inside that image, `renv::restore()` installed the 19 (binaries,
  5 s) and `renv::status()` reports the project consistent; `library(ggplot2)` under
  `RENV_PROJECT` and `R_PROFILE_USER` loads from the project library. A `README.md` beside it
  says how to build and extend it.
- `envs/manifest.yml` names both; the template's `.gitignore` keeps `.venv/` and renv's
  library out; the template README's table and `docs/method-author.md` name the two examples
  and say when an image is still the only choice (Nextflow and its containers, binaries,
  system libraries, a Bioconductor set with no arm64 binaries).
- `tests/test_template.py`: the template lints clean and the two locks are where the manifest
  says.

**Learned.** renv's scaffold pins the renv version it will bootstrap, and the bootstrap
downloads that version from the lock's repository: the first lock, written against the image's
default snapshot (2026-04-23, renv 1.2.2), could not bootstrap renv 1.2.4 anywhere without a
`curl` binary. The snapshot and the scaffold's renv must agree; 2026-09-01 carries 1.2.4 and
every pin as its current version.
An environment directory with no scripts needs the explicit snapshot type and a `DESCRIPTION`,
or `renv::status()` calls it out of sync; and the lock must record renv itself, which
`lockfile_create(packages = ...)` does only when asked.

**Altered.** Nothing in a contract; the template gains two directories.

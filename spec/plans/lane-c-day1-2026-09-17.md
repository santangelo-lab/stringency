## The ROSC cell-area join (defect A1) and how this plan guards against it

ROSC_MTA's `AppendAreaParquet` (`Xen_Seurat_functions.R:135`) called `match()` with its arguments
reversed. Because `cells.parquet` is sorted by `cell_id`, the h5 is not, and both hold the same id
set, the result was a complete permutation with zero `NA`s: every `cell_area` and `nucleus_area`
landed on the wrong cell, the area QC filter removed the wrong 1.6 to 28 percent of cells per
tissue, and `LogArea` normalisation carried the error into PCA and clustering. An `anyNA()` guard
could not see it; only a value-level identity check could. It cost a full reprocessing of eleven
tissues (`ROSC_MTA2/setup/Claude/BUG_cell_area_join.md`, `cell_area_bug_assessment.md`).

`qc-cells` performs exactly this join again, in Python. The guards, each of which alone would have
caught A1:

1. **Keyed join only.** `qc-cells` indexes `cells.parquet` by `cell_id` and aligns it to the h5
   barcodes with an explicit key lookup (`reindex` on the barcode array). No positional
   concatenation, no `match`-style index arithmetic. The module docstring cites A1.
2. **Value-level assertion after the join.** For every cell, `obs.index == barcode` and the
   joined `cell_area` equals the value looked up independently by id from the parquet. Set
   equality and zero missing values are checked too, but are stated in the code as insufficient.
3. **A fixture that makes positional joins fail.** The synthetic bundle writes h5 barcodes in a
   shuffled order relative to `cells.parquet` and gives `cell_area` a known function of
   `cell_id`; a must-fire test performs a positional join and shows the assertion catching it,
   the way ROSC_MTA2's `test-area-join.R` documents that `anyNA` would not have.
4. **Order agreement recorded, not assumed.** The `xenium_bundle` extractor records whether h5
   order matches parquet order, and the fixed splitter (C1) makes them agree in punch bundles;
   that is a convenience, not a guard, and `qc-cells` must not depend on it.
5. **Predicate `sc.area_join_unverified`** (block): fires when a `qc-cells` execution lacks the
   join-verification evidence line in its output sidecar. Added to C2 step 7.

### Parallel Proseg without OOM (plan, 18:45 local)

Facts: 502 GB RAM, 7 GB swap, 88 cores; `systemd-oomd` active. A user scope with
`systemd-run --user --scope -p MemoryMax=<cap> -p MemorySwapMax=0` **hard-caps** a job (tested:
400 MB touched under a 200 MB cap is killed, exit 137; without `MemorySwapMax=0` the process
swaps instead). So every region's Nextflow launch runs in its own scope with a budget, and an
overrun kills only that region's Proseg; Nextflow `-resume` restarts that process alone.

Budget rule: cap = 1.5 × the peak measured on the first lung (0076581, 47 M transcripts),
scaled by transcripts (gut 89 to 113 M is 1.9 to 2.4× the lung), plus 130 GB reserved for one
XeniumRanger import at a time (`rangerimportMem 128`) and 60 GB for the rest of the machine
(splits peak at 83 GB, so no split runs while two guts are in Proseg). Cores: 16 threads per
Proseg; Proseg showed ~7 cores busy at 16 threads early on, so three concurrent regions are ~48
cores nominal, well under 88.

Schedule (fill in the measured peak P): if P ≤ 40 GB, run the second lung now (cap 60) and both
guts (cap 1.5 × 2.4 × P ≈ 145 each) as soon as the first lung's Proseg finishes; total ≤ 60 +
290 + 130 + 60 = 540 → too tight, so start the second gut when the first lung's import is done.
If P is 40 to 80 GB, one gut at a time. If P > 80 GB, no concurrency; the ROSC brain region
reached 82 GB. XeniumRanger imports are serialised by launching each region's pipeline with a
staggered start, not by Nextflow.

### Evening operator-run lessons (20:30 local)

- An operator ticket `awaiting_execution` cannot be re-proposed or failed: `propose` refuses
  ("cannot be proposed now") and `submit` has no failure path, so a failed external run forces
  `abandon` + `propose --new`. Lane A: `submit --failed --reason` (attempt 2 on the same run).
- Nextflow's launcher runs `env - PATH=... apptainer exec`, so environment-based apptainer
  settings (`APPTAINER_BIND`) never reach the container; binds must be in `apptainer.runOptions`.
- Nextflow's resume cache lives in the launch directory (`.nextflow/cache`), not the work dir:
  a new step directory resumes only after copying `.nextflow/` from the previous launch.
- The pipeline's clamp step wrote symlinked bundles (`4b6793f` on `dev` fixes it); the ROSC runs
  never hit this because Docker bound the raw data under its own path.
